# Result 14: cross-grammar problem card and routed construction

## Question and obstruction

The worktable had a coherent conceptual sequence but no single executable entry
point. A caller had to choose `construct_target_relation`,
`compile_single_source_functional`, `construct_observable_closure`,
`construct_event`, or `construct_path_functionals` before invoking the tool. The
resulting collection could not itself demonstrate that the shared semantic
contract was operational.

The repair is not a universal mathematical representation. The existing request
types preserve distinctions that matter to their physics and certificates. The
smallest new object is therefore a typed problem card with one admitted semantic
request and one explicit selection point.

## Frozen local contract `C-router-v1`

The contract was fixed before the heterogeneous bench ran:

```text
ProblemCard(problem_id, observable, provenance, semantic request,
            optional same-observable route pair)
  -> selected existing operator
  -> original domain construction
  -> normalized status and source status
  -> selection witness
  -> domain certificates or preserved obstruction
  -> optional exact handwritten admission boundary.
```

The admitted request domain is:

- an unordered bag of provenance-bearing exact relations with givens and target;
- one source-to-field functional packet;
- finite rational repeated linear dynamics and a target covector;
- a finite exact polynomial event with physical intervals; or
- an exact planar field with oriented parameterized paths.

The router may not inspect a problem identifier or expected answer to select an
operator. A one-law relation packet is classified as direct only when the selected
law contains no hidden quantity. An optional cost boundary may be constructed only
after mathematical success and only from two independently inspectable routes for
the same problem, target, and execution substrate.

### Falsifiers

`C-router-v1` is rejected or restricted if selection depends on source identity,
if a domain result or certificate is lost, if ambiguity is silently resolved, if
an unsupported backend is treated as physical underdetermination, or if route cost
changes the mathematical-success disposition.

### Promotion conditions

The bounded orchestration claim is promoted only if one unchanged public operation
passes a direct relation, a hidden-variable projection, the three distinct
structural request kinds, a transfer, adversarial ambiguity, unsupported algebra,
and a downstream use/cost rejoin.

## Constructed operation

`occ/routing.py` owns `ProblemCard` and `compile_problem_card`. Wrapper requests
exist only for the two older functions that lacked a request object: functional
extraction with `max_fields`, and linear dynamics with `max_dimension`. All domain
mathematics remains in its previous owner.

The selection is determined by admitted semantic structure:

```text
unordered laws       -> minimal relation constructor
                         -> direct relation when one law/no hidden quantity
                         -> polynomial relation otherwise
source functional    -> semantic extractor and pullback
linear dynamics      -> obstruction-generated observable closure
event predicate      -> event projection, full-state lift, domain filter
oriented paths       -> path-functional constructor
```

The common result retains the original construction rather than translating it
into a weaker universal record. Normalization adds only orchestration status,
operator, source status, selection witness, certificates, domain obstruction, and
optional admission boundary.

The frozen implementation budget was `routing.py <= 280`, routing fixtures
`<= 220`, and focused tests `<= 160` physical lines. The completed counts are 279,
210, and 148 respectively; the common layer therefore remains smaller than the
specialist implementations it coordinates.

## Decision kernel `K-router-v1`

The synthesis uses these frozen rules:

1. exact in-domain success supports only the matched construction dimension;
2. unchanged use on a structurally different card supports bounded transfer;
3. ambiguity and unsupported shape support refusal behavior, not solution reach;
4. the A15 cost result affects use only and cannot negate event correctness;
5. regression does not establish transfer, transfer does not establish cost, and
   no finite bench establishes universal coverage or novelty;
6. absent learner observations leave every learner claim unresolved.

## Re-entry conditions

Reopen `C-router-v1` if a new operator requires more than one semantic request in a
card, if a domain certificate cannot cross the envelope, or if unseen cards expose
ambiguous type-level selection. The next internal research question is whether an
out-of-grammar source problem can construct a new semantic request type from a
calculated obstruction and then recover an old routed case. Learner claims re-enter
only when the validated observation table contains correct provenance-bearing
pairs.
