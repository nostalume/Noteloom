# N10j computation — generated curvature compatibility

Run from the repository root:

```powershell
node physics/quantum-mechanics/relativistic-representations-research/computation/10j-generated-curvature-compatibility/check-curvature-compatibility.mjs
```

The constructor consumes the symmetric-potential system generated by N10c, the
chiral bivector split constructed in N2b, a positive integer spin, and a derivative
budget. It does not receive a generalized-curvature formula.

The node proves that the target chiral weight first becomes reachable at polynomial
degree `s` and occurs once there. The executable multiplicity trace encodes this
theorem; it does not calculate a general Hom space. A lower budget returns a
polynomial-lift refusal. The spin-indexed operation applies the chiral projections of `p wedge v` to
each symmetric potential slot and multiplies their outputs. Gauge annihilation is
internal: a pure-gradient input contains the factor `b_+(p,p)=b_-(p,p)=0`.

The executable evaluator represents symmetric spinors as homogeneous polynomials,
not spacetime tensor components. For spins one through six it checks:

- the encoded minimal-degree/multiplicity regression;
- annihilation of the gradient gauge image;
- nonzero recovery of both null-screen endpoint lines;
- covariance under two independent determinant-one spinor transformations;
- consumption by N10i as a new spin-two curvature-output capability;
- refusal of an unsupported polynomial local inverse.

The artifact retains a local forward curvature evaluator and verifies the
physical-shell quotient isomorphism. It does not generate its target carrier or
multiplicity theorem, a local inverse, a sourced curvature Green complex, or an
interacting deformation. See the [construction-origin audit](../../results/07-construction-origin-audit.md).
